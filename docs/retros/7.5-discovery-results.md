## Case 1: Plausible — Starter ~10k pageviews

| Field | Value |
|-------|-------|
| **URL** | https://plausible.io/ (homepage, not /pricing) |
| **Target** | Starter plan, monthly USD, default ~10k pageviews band |
| **Expected** | **$9/month** |
| **Extracted** | **$9/month** ✓ |
| **Ladder step** | **2** — HTTP + DOM/regex |
| **Method** | `dom` — regex on SSR HTML |
| **Skill path** | `data/skills/plausible-io.json` |
| **LLM tokens** | **0** |
| **Wall time** | ~53 ms (fetch + extract) |
| **Page loads** | 1 |

### Selectors & extraction notes

- Plausible uses Alpine.js with `x-text` bindings. The server-side rendered HTML
  contains the default price value inline:
  ```
  x-text="price(currency, volumeIndex, 'starter', 'monthly')"> $9 </span>
  ```
- Regex: `price\(.*?'starter'.*?'monthly'\).*?\$(\d+)`
- The pricing is on the **homepage** (not a separate /pricing page). The homepage
  has a volume slider that defaults to ~10k pageviews; other bands ($14, $19, …)
  also appear but the regex targets only the `'starter'` + `'monthly'` combo.
- No Cloudflare challenge; page served directly with 200 OK.

### Risks

- If Plausible moves away from SSR (pure client-side Alpine hydration), the
  default value may stop appearing in the initial HTML. Would require Step 3+.
- Volume band selector is Alpine-driven; the $9 is the default render only.

## Case 2: Linear — Basic seat price

| Field | Value |
|-------|-------|
| **URL** | https://linear.app/pricing |
| **Target** | Basic plan, per user/month USD |
| **Expected** | **$10 per user/month** |
| **Extracted** | **$10 per user/month** ✓ |
| **Ladder step** | **2** — HTTP + DOM/regex |
| **Method** | `dom` — regex on SSR HTML |
| **Skill path** | `data/skills/linear-app.json` |
| **LLM tokens** | **0** |
| **Wall time** | ~128 ms |
| **Page loads** | 1 |

### Selectors & extraction notes

- Linear SSR renders pricing cards with `id="basic"` section headers.
- Inside the Basic card, there is a visually-hidden accessibility span:
  ```html
  <span class="…visuallyHidden">$10 per user/month</span>
  ```
  and an `aria-label="$10 per user/month"` on a `<number-flow-react>` element.
- Regex: `id="basic".*?\$(\d+)\s+per\s+user/month` (scoped to 3k chars after `id="basic"`)
- The page has a "Billed yearly" toggle which is **checked by default** — the $10/user/month
  displayed is the yearly-billed rate. The monthly-billed rate is higher. We extract
  the labeled price exactly as shown on page load.
- No Cloudflare challenge.

### Gotchas

- The price is inside a `<number-flow-react>` custom element (animation library).
  The visually-hidden span is the reliable SSR target; the animated element may
  not have stable text in raw HTML.
- "Billed yearly" is the default view — extracting $10 is correct per the page's
  labeled Basic seat price, not a yearly-total misread.

## Case 3: Notion — Plus per member

| Field | Value |
|-------|-------|
| **URL** | https://www.notion.com/pricing |
| **Target** | Plus plan, per member/month USD (ignore AI add-ons) |
| **Expected** | **$10 per member/month** |
| **Extracted** | **$10 per member/month** ✓ |
| **Ladder step** | **2** — HTTP + DOM/regex |
| **Method** | `dom` — regex on SSR HTML + embedded JSON validation |
| **Skill path** | `data/skills/notion-com.json` |
| **LLM tokens** | **0** |
| **Wall time** | ~202 ms |
| **Page loads** | 1 |

### Selectors & extraction notes

- **Dual extraction strategy:**
  1. **Embedded JSON** — Notion SSR includes structured pricing data in the HTML.
     The Plus plan entry: `"plus":{"USD":{"month":{"unit_amount":1200},"year":{"unit_amount":12000}}}`.
     - Monthly rate: 1200 cents = $12/month
     - Yearly rate: 12000 cents = $120/year = **$10/month** (billed annually)
  2. **DOM headings** — `PricingPlanCard` module with paired headings:
     `heading">Plus</h3>` followed by `heading">$10</span>`

- The page defaults to **annual billing** display, showing $10/member/month.
- Both strategies agree on $10. The JSON additionally reveals the true monthly
  rate ($12) for future monitoring if billing toggle behavior changes.

### Gotchas — yearly vs monthly

- The labeled price on the page is $10/member/month (billed yearly). This is
  the correct target per the task. The monthly-only price is $12 but is not
  the default display.
- **AI add-on prices** also appear on the page ($10 per 1,000 credits) — the
  extractor ignores these by targeting the Plus plan card heading pair specifically.
- Notion uses hashed CSS class names (e.g. `PricingPlanCard-module-scss-module__AkOUza__heading`);
  the hash segment may change on redesigns. The regex targets the stable
  `heading">Plus` → `heading">$N` pattern which should survive minor restyling.

   Linear's accessibility spans are the most stable.
