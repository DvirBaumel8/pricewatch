## Case 1: Vercel — Pro $20/developer seat/month

| Field | Value |
|-------|-------|
| **URL** | https://vercel.com/pricing |
| **Target** | Pro plan, $20 per developer seat / month |
| **Expected** | **$20 per developer seat / month** |
| **Extracted** | **$20 per developer seat / month** |
| **Ladder step** | **2** — HTTP + DOM/regex |
| **Method** | `dom` — RSC embedded JSON + DOM heading validation |
| **Skill path** | `data/skills/vercel-com.json` |
| **LLM tokens** | **0** |
| **Wall time** | ~249 ms (fetch + extract) |
| **Page loads** | 1 |

### Extraction strategy

**Triple validation (all agreed on $20):**

1. **RSC embedded JSON** — Vercel's pricing page is a Next.js RSC app. The HTML
   contains an escaped JSON payload with:
   ```
   \"planPrices\":{\"pro\":{\"amount\":\"$$20\",\"suffix\":\"/mo.\"}}
   ```
   The `$$` prefix is Vercel's escaping convention in RSC payloads.

2. **DOM heading** — The Pro section has a "Popular" badge followed by:
   ```html
   <span class="text-heading-32 @lg:text-heading-56 font-[450]! text-gray-1000">$20</span>
   <span class="text-label-14-mono normal-case text-gray-900">/mo.</span>
   ```

3. **Feature table** — The "Developer seat" row in the comparison table:
   ```
   \"Developer seat\"...\"proTitle\":\"$$20 / month\"
   ```

### Promo traps avoided

- `$20 of included usage credit` — appears in FAQ text; not the plan price
- `$20 per 1M` — workflow events unit pricing; not the seat price
- `$20 / project / month` — password protection add-on; not the seat price
- `$0/mo.` — Hobby tier; scoped out by targeting Pro section specifically

### Risks

- RSC payload format may change across Next.js versions. The DOM heading is a
  stable fallback but requires scoping to the "Popular" badge area to avoid
  matching Hobby's $0.
- Page is 1.1 MB — large but not blocked.

## Case 2: Slack — Pro $8.75/active user/month (monthly billing)

| Field | Value |
|-------|-------|
| **URL** | https://slack.com/pricing |
| **Target** | Pro plan, $8.75 USD per active user / month, paying monthly |
| **Expected** | **$8.75 per active user / month** |
| **Extracted** | **$8.75 per active user / month** |
| **Ladder step** | **2** — HTTP + DOM/regex |
| **Method** | `dom` — regex on SSR HTML |
| **Skill path** | `data/skills/slack-com.json` |
| **LLM tokens** | **0** |
| **Wall time** | ~1074 ms (fetch + extract) |
| **Page loads** | 1 |

### Extraction strategy

Slack's pricing page renders plan cards with class `plan-type--pro`. Inside the
Pro card, the pricing structure during a promotional period is:

```html
<span class="v--strikeprice">$8.75</span>
<span data-js-billing-type="monthly" class="plan-emphasized-rate">$4.38<span class="plan-currency">USD</span></span>
```

- The **strikethrough price** (`v--strikeprice`) contains the **standard** monthly rate: **$8.75**
- The **emphasized rate** is the current 50%-off promo: $4.38 (ignored)
- The term text confirms: `"per user / month, when paying monthly"`

The extractor targets the `v--strikeprice` span within the `plan-type--pro`
section, correctly extracting the standard (non-promotional) price.

### Promo traps avoided

- `$4.38` — 50% off for 3 months promo; correctly ignored by targeting strikeprice
- Annual pricing — not shown by default in the monthly billing view
- `$18` strikeprice for Business+ — scoped out by targeting only the Pro section
- Free tier — has no price display; no risk of confusion

### Risks

- When the promo ends, the `v--strikeprice` class may disappear. The extractor
  would need to fall back to `plan-emphasized-rate` or a different selector.
  Adding a fallback for non-promo layout would improve robustness.
- Slack's page is ~700 KB, served without Cloudflare challenge.

## Case 3: Shopify — Basic $29/mo (standard)

| Field | Value |
|-------|-------|
| **URL** | https://www.shopify.com/pricing |
| **Target** | Basic plan, standard $29/mo |
| **Expected** | **$29/month** |
| **Extracted** | **$29/month** |
| **Ladder step** | **2** — HTTP + DOM/regex |
| **Method** | `dom` — regex on SSR HTML |
| **Skill path** | `data/skills/shopify-com.json` |
| **LLM tokens** | **0** |
| **Wall time** | ~97 ms (fetch + extract) |
| **Page loads** | 1 |

### Extraction strategy

Shopify renders pricing cards with a heading pair inside a `text-t7` styled div:

```html
<div class="flex justify-between items-center text-t7">
  <p>Basic</p>
  <p> <!-- -->$29<small class="text-xs">/mo</small></p>
</div>
```

The regex targets `text-t7"><p>Basic</p><p>` followed by `$(\d+)<small…>/mo`.

**Cross-validation from comparison table:**
- "Pay yearly" row: `$29 USD/mo` (annual-billing rate, matches card)
- "Pay monthly" row: `$39 USD/mo` (monthly-only rate, higher)

The card's $29/mo is the standard annual-billing rate, which is the price Shopify
prominently displays and advertises as the plan price.

### Promo traps avoided

- `$1/month for 3 months` — intro promo prominently shown on page; correctly ignored
- `$39 USD/mo` — monthly-only rate (not the standard advertised price); noted but not extracted
- `$299/mo` — Advanced plan; scoped out by targeting `Basic` in the heading pair
- `$399` — Advanced monthly rate; not in scope

### Risks

- Shopify periodically changes intro promo amounts ($1, $3, etc.). The extractor
  is immune to this since it targets the card heading, not the promo banner.
- The `text-t7` class is a Tailwind utility and should be stable, but the card
  layout could change on a full redesign.
- Page is 1.1 MB — large but served without blocks.

## Notes on promo traps

These 3 sites all have significant promo traps that a naive `$(\d+)` regex would hit:

| Site | Trap | How we avoided it |
|------|------|------------------|
| Vercel | `$20 per 1M` (workflow events), `$20 / project` (password protection), `$0` (Hobby) | Scoped to `planPrices.pro.amount` in RSC JSON; DOM scoped to "Popular" badge section |
| Slack | `$4.38` (50% off promo), `$18` (Business+ strikeprice) | Targeted `v--strikeprice` within `plan-type--pro` section only |
| Shopify | `$1/month for 3 months` (intro promo), `$39/mo` (monthly-only), `$299/mo` (Advanced) | Targeted card heading pair `<p>Basic</p><p>…$29…/mo</p>` |

## Recommendations

1. **No Playwright dependency needed** for these 3 cases. All work with plain
   `http.get` + regex at Step 2.
2. **Slack's promo layout is fragile** — when the promo ends, the `v--strikeprice`
   class will likely disappear. Should add a non-promo fallback path that reads
   `plan-emphasized-rate` directly when no strikeprice exists.
3. **All 3 pages are large** (700KB–1.1MB) but serve clean SSR HTML without
   JS-only rendering or Cloudflare challenges.
4. **Monitor stability**: Vercel (RSC JSON) and Shopify (card heading) are the
   most stable targets. Slack (promo-dependent selector) is the most fragile.
